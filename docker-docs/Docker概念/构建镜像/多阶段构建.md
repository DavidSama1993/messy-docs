# 多阶段构建（Multi-stage builds）
## 讲解
传统构建方式里，所有构建指令按顺序在同一个构建容器中执行：下载依赖、编译代码、打包应用。所有这些层最终都会被放进最终镜像。这种方式虽然能用，但会造成镜像体积庞大，包含很多不必要内容，同时增大安全攻击面。**多阶段构建**就是用来解决这个问题的。

多阶段构建在一份 Dockerfile 里划分多个阶段，每个阶段各司其职。可以理解为：把构建流程的不同环节放到多个独立环境中运行。将**构建环境**和**运行时环境**分开，能够大幅缩小镜像体积、缩减攻击面，对于依赖庞大的应用效果尤其明显。

所有类型应用都推荐使用多阶段构建：
- 解释型语言（JavaScript、Ruby、Python）：在一个阶段完成打包、代码压缩，再把可直接上线的产物拷贝到更轻量的运行镜像中，优化部署镜像。
- 编译型语言（C、Go、Rust）：在构建阶段完成编译，只把编译好的二进制文件拷贝到最终运行镜像，最终镜像不需要携带编译器。

下面是简化的伪代码示例，多阶段构建会出现多条 `FROM`，搭配 `AS <阶段名>`；后续阶段的 `COPY` 可以通过 `--from` 从前面阶段拷贝文件：
```dockerfile
# 阶段1：构建环境
FROM builder-image AS build-stage 
# 安装构建工具（如 Maven、Gradle）
# 拷贝源码
# 执行构建命令（编译、打包）

# 阶段2：运行时环境
FROM runtime-image AS final-stage  
# 从构建阶段拷贝产物（例如 JAR 包）
COPY --from=build-stage /path/in/build/stage /path/to/place/in/final/stage
# 配置运行参数（CMD、ENTRYPOINT）
```

这份 Dockerfile 包含两个阶段：
- 构建阶段：使用预装编译工具的基础镜像，安装构建依赖、拷贝源码、执行打包编译。
- 最终阶段：选用轻量化运行镜像，只从构建阶段拷贝编译产物（如 JAR 包），再配置启动命令。

## 动手实践
本次实操，用多阶段构建为一个简单 Java Spring Boot 示例生成精简的 Docker 镜像。示例是基于 Maven 的 Hello World Spring Boot 应用。

1. 安装 Docker Desktop
2. 打开 [Spring Initializr](https://start.spring.io/#!type=maven-project&language=java&platformVersion=4.0.1&packaging=jar&configurationFileFormat=properties&jvmVersion=21&groupId=com.example&artifactId=spring-boot-docker&name=spring-boot-docker&description=Demo%20project%20for%20Spring%20Boot&packageName=com.example.spring-boot-docker&dependencies=web) 生成项目压缩包
Spring Initializr 是 Spring 项目脚手架，可快速生成 Java/Kotlin/Groovy 的 Maven/Gradle 项目。
参数选择：Java 21、Spring Web、Spring Boot 4.0.1，点击 Generate 下载 zip。

3. 解压文件，项目目录结构：
```plaintext
spring-boot-docker
├─ HELP.md
├─ mvnw
├─ mvnw.cmd
├─ pom.xml
└─ src
    ├─ main
    │   ├─ java
    │   │   └─ com
    │   │       └─ example
    │   │           └─ spring_boot_docker
    │   │               └─ SpringBootDockerApplication.java
    │   └─ resources
    │       ├─ application.properties
    │       ├─ static
    │       └─ templates
    └─ test
        └─ java
            └─ com
                └─ example
                    └─ spring_boot_docker
                        └─ SpringBootDockerApplicationTests.java
```
`src/main/java` 存放业务源码；`src/test/java` 存放测试代码；`pom.xml` 是 Maven 的项目对象模型（POM），Maven 的核心配置文件。

4. 编写 REST 接口，返回 Hello World
修改 `src/main/java/com/example/spring_boot_docker/SpringBootDockerApplication.java`：
```java
package com.example.spring_boot_docker;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;


@RestController
@SpringBootApplication
public class SpringBootDockerApplication {

    @RequestMapping("/")
        public String home() {
        return "Hello World";
    }

	public static void main(String[] args) {
		SpringApplication.run(SpringBootDockerApplication.class, args);
	}
}
```
这个文件定义包、导入 Spring 依赖，实现一个简单 Web 服务，访问首页返回 Hello World。

### 编写 Dockerfile（非多阶段版本）
1. 在项目根目录新建 Dockerfile（和 src、pom.xml 同级）
2. 编写内容：
```dockerfile
FROM eclipse-temurin:21.0.8_9-jdk-jammy
WORKDIR /app
COPY .mvn/ .mvn
COPY mvnw pom.xml ./
RUN ./mvnw dependency:go-offline
COPY src ./src
CMD ["./mvnw", "spring-boot:run"]
```
- `dependency:go-offline`：提前下载全部依赖，不打包 JAR，提升后续构建速度

### 构建镜像
```console
$ docker build -t spring-helloworld .
```
查看镜像大小
```console
$ docker images
```
输出示例：
```console
REPOSITORY          TAG       IMAGE ID       CREATED          SIZE
spring-helloworld   latest    ff708d5ee194   3 minutes ago    880MB
```
镜像 880MB，里面包含完整 JDK、Maven 全套构建工具；生产环境其实不需要这些构建工具。

### 运行 Spring Boot 应用
```console
$ docker run -p 8080:8080 spring-helloworld
```
容器启动日志会打印 Spring Boot 的启动横幅。
浏览器访问 http://localhost:8080，或者 curl 测试：
```console
$ curl localhost:8080
Hello World
```

### 使用多阶段构建改造 Dockerfile
改造后的多阶段 Dockerfile：
```dockerfile
FROM eclipse-temurin:21.0.8_9-jdk-jammy AS builder
WORKDIR /opt/app
COPY .mvn/ .mvn
COPY mvnw pom.xml ./
RUN ./mvnw dependency:go-offline
COPY ./src ./src
RUN ./mvnw clean install

FROM eclipse-temurin:21.0.8_9-jre-jammy AS final
WORKDIR /opt/app
EXPOSE 8080
COPY --from=builder /opt/app/target/*.jar /opt/app/*.jar
ENTRYPOINT ["java", "-jar", "/opt/app/*.jar"]
```
- builder 阶段：带完整 JDK，用来编译打包，生成 jar 产物
- final 阶段：只包含 JRE（Java 运行时，不含编译器），从 builder 阶段拷贝打好的 jar 包

> 生产建议：可以用 jlink 自定义裁剪 JRE，只保留应用需要的 Java 模块，进一步缩小镜像、提升安全性。

构建多阶段镜像：
```console
$ docker build -t spring-helloworld-builder .
```
> 说明：多阶段构建默认构建最后一个阶段（final）；如果只想构建 builder 阶段，可以加 `--target builder`：
> `docker build -t spring-helloworld-builder --target builder .`

再次查看镜像大小：
```console
$ docker images
```
```console
spring-helloworld-builder latest    c5c76cb815c0   24 minutes ago      428MB
spring-helloworld         latest    ff708d5ee194   About an hour ago   880MB
```
优化后镜像仅 428MB，功能不变，体积减半，镜像更轻量、攻击面更小、更容易分发管理。
