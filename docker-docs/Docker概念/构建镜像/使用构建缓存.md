# 使用构建缓存
## 讲解
以下是前面入门应用用到的 Dockerfile：
```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY . .
RUN yarn install --production
CMD ["node", "./src/index.js"]
```

执行 `docker build` 构建镜像时，Docker 会按顺序执行 Dockerfile 的每一条指令，每条指令生成一个镜像层。对于每一条指令，Docker 会检查是否可以复用上一次构建的缓存。如果判定指令没有变化，就不会重复执行，直接复用缓存结果，从而加快构建速度、节省时间与资源。

合理利用构建缓存，可以复用之前的构建结果，跳过重复耗时步骤。想要最大化缓存利用率、避免不必要的全量重建，需要理解**缓存失效**的规则。
下面这些情况会触发缓存失效：
- `RUN` 后的命令发生修改：Dockerfile 里 RUN 命令内容一变，当前层缓存直接失效。
- `COPY` / `ADD` 拷贝的文件发生变化：项目内文件内容、权限等属性改动，都会让缓存失效。
- 某一层缓存失效后，**它后面所有层全部跟着失效**：基础镜像或中间层一旦失效，依赖它的后续层都要重新构建，保证构建结果一致。

编写 Dockerfile 时，尽量避免不必要的缓存失效，保证构建高效。

## 动手实践
本次实操，学习在 Node.js 项目中高效使用 Docker 构建缓存。
### 构建应用
1. 安装 Docker Desktop
2. 终端克隆示例项目
```console
$ git clone https://github.com/dockersamples/todo-list-app
```
3. 进入项目目录
```console
$ cd todo-list-app
```
目录内自带 Dockerfile：
```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY . .
RUN yarn install --production
EXPOSE 3000
CMD ["node", "./src/index.js"]
```
4. 执行构建
```console
$ docker build .
```
构建输出：
```console
[+] Building 20.0s (10/10) FINISHED
```
首次构建耗时较长，主要是下载安装依赖。

5. 不修改任何代码，再次构建
```console
$ docker build .
```
只要 Dockerfile 和上下文文件没变，就会复用缓存层，速度大幅提升：

第二次仅耗时 1 秒，不再重复执行依赖安装这类耗时操作。

|步骤|说明|首次耗时|二次耗时|
| ---- | ---- | ---- | ---- |
|1|加载 Dockerfile 构建定义|0.0s|0.0s|
|2|拉取 node:22-alpine 元数据|2.7s|0.9s|
|3|加载 .dockerignore|0.0s|0.0s|
|4|加载构建上下文（上下文大小：4.60MB）|0.1s|0.0s|
|5|设置工作目录 WORKDIR|0.1s|0.0s|
|6|拷贝本地代码到容器|0.0s|0.0s|
|7|执行 yarn install --production|10.0s|0.0s|
|8|导出镜像层|2.2s|0.0s|
|9|导出最终镜像|3.0s|0.0s|

回顾 `docker image history` 的输出：Dockerfile 的每一条命令都会成为镜像里独立的一层。
上面这个写法有明显短板：只要业务代码改动，`COPY . .` 就会失效，后面的 `yarn install` 就要重新执行。每次改前端页面都重装依赖，非常浪费时间。

优化思路：**拆分拷贝步骤，先拷贝依赖描述文件，安装依赖，最后再拷贝业务代码**。
对于 Node 项目，依赖定义在 `package.json`、`yarn.lock`；只有这两个文件改动时，才需要重装依赖；单纯改业务代码，依赖层缓存保留。

6. 修改 Dockerfile，调整拷贝顺序
```dockerfile
FROM node:22-alpine
WORKDIR /app
COPY package.json yarn.lock ./
RUN yarn install --production 
COPY . . 
EXPOSE 3000
CMD ["node", "src/index.js"]
```

7. 在 Dockerfile 同级新建 `.dockerignore`
```plaintext
node_modules
```

8. 重新构建镜像
```console
$ docker build .
```
