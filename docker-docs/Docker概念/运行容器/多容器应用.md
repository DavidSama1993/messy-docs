# 多容器应用（Multi-container applications）
## 讲解
单容器应用启动起来很简单。例如，一个执行特定数据处理任务的Python脚本，可以连同全部依赖放在一个容器里运行；同样，提供静态网站和小型API接口的Node.js应用，也可以打包进单个容器。但随着应用体量变大，全部组件放在同一个容器里会越来越难维护。

设想这个Python数据脚本需要连接数据库：这时你不仅要管理脚本本身，还要在同一个容器里维护数据库服务。如果脚本还需要用户登录功能，你又得加入鉴权模块，容器体积会变得臃肿。

容器的一条最佳实践：**一个容器只做一件事，并且做好这件事**。虽然存在例外，但尽量不要让单个容器承担多项职责。

你可能会问：那这些容器是不是要分开启动？分开启动之后，怎么把它们连通起来？

`docker run` 虽然启动容器很方便，但应用栈变复杂之后就不好管理了，原因如下：
- 前端、后端、数据库，开发/测试/生产三套环境，要写一大堆不同配置的 `docker run` 命令，容易出错、耗时；
- 服务之间存在依赖，手动按顺序启动容器、配置网络连通，服务多了很难维护；
- 每个服务单独用一条命令，单独扩容某个服务不方便；整体扩容又会给不需要扩容的组件浪费资源；
- 每个服务的数据持久化，都要在各自run命令里写卷挂载配置，数据配置分散；
- 逐个命令配置环境变量，重复繁琐，极易写错。

这就是 **Docker Compose** 的作用。

Docker Compose 在一个 `compose.yml` YAML 文件中定义整套多容器应用，里面包含所有容器配置、服务依赖、环境变量、卷、网络。使用 Compose 带来这些好处：
- 不用执行多条 `docker run`，所有配置集中在一份文件，便于维护；
- 自动按依赖顺序启动容器，网络连通自动处理；
- 可以单独对某个服务扩容、缩容，按需分配资源；
- 卷持久化配置简单；
- 环境变量统一在 Compose 文件里声明，一次配置。

借助 Docker Compose 部署多容器架构，可以搭建出模块化、可扩展、配置一致的复杂应用。

## 动手实践
本节实操，先用多条 `docker run` 搭建一套计数器Web应用（Node.js后端 + Nginx反向代理 + Redis），再改用 Docker Compose 简化整套部署流程。

### 准备工作
1. 获取示例代码，二选一：
**Git克隆**
```console
$ git clone https://github.com/dockersamples/nginx-node-redis
$ cd nginx-node-redis
```
目录下包含 `nginx` 和 `web` 两个子文件夹。

**下载压缩包**
[Download the source](https://github.com/dockersamples/nginx-node-redis/archive/refs/heads/main.zip)
解压后进入目录：
```console
$ cd nginx-node-redis-main
```

2. 安装 Docker Desktop

### 构建镜像
1. 进入 nginx 目录构建镜像
```console
$ docker build -t nginx .
```
2. 进入 web 目录构建web镜像
```console
$ docker build -t web .
```

### 启动容器
1. 先创建独立网络，供所有容器互相通信
```console
$ docker network create sample-app
```
2. 启动Redis容器，接入该网络并设置网络别名（用于DNS解析）
```console
$ docker run -d  --name redis --network sample-app --network-alias redis redis
```
3. 启动第一个web后端
```console
$ docker run -d --name web1 -h web1 --network sample-app --network-alias web1 web
```
4. 启动第二个web后端
```console
$ docker run -d --name web2 -h web2 --network sample-app --network-alias web2 web
```
5. 启动Nginx反向代理容器，对外暴露80端口
```console
$ docker run -d --name nginx --network sample-app  -p 80:80 nginx
```
> 说明：Nginx在这里作为反向代理，把请求转发给后端Node服务（web1 / web2）

6. 查看容器是否正常运行
```console
$ docker ps
```
输出示例：
```text
CONTAINER ID   IMAGE     COMMAND                  CREATED              STATUS              PORTS                NAMES
2cf7c484c144   nginx     "/docker-entrypoint.…"   9 seconds ago        Up 8 seconds        0.0.0.0:80->80/tcp   nginx
7a070c9ffeaa   web       "docker-entrypoint.s…"   19 seconds ago       Up 18 seconds                            web2
6dc6d4e60aaf   web       "docker-entrypoint.s…"   34 seconds ago       Up 33 seconds                            web1
008e0ecf4f36   redis     "docker-entrypoint.s…"   About a minute ago   Up About a minute   6379/tcp             redis
```

7. 在Docker Desktop面板查看所有容器与配置。
8. 浏览器打开 http://localhost，多次刷新页面，可以看到不同后端在处理请求，以及访问计数：
```console
web2: Number of visits is: 9
web1: Number of visits is: 10
web2: Number of visits is: 11
web1: Number of visits is: 12
```
> 说明：Nginx 默认轮询（round-robin）分发流量，请求轮流交给 web1、web2；计数保存在Redis中。

9. 可在Docker面板选中容器，批量删除。

### 使用 Docker Compose 简化部署
整套应用全部定义在项目根目录的 `compose.yml` 文件中，包含所有服务、镜像、端口、卷、网络配置。

1. 在项目根目录执行命令启动（自动构建镜像、后台启动）
```console
$ docker compose up -d --build
```
输出示例：
```console
 ✔ Network nginx-node-redis_default   Created
 ✔ Container nginx-node-redis-web2-1  Created
 ✔ Container nginx-node-redis-web1-1  Created
 ✔ Container nginx-node-redis-redis-1 Created
 ✔ Container nginx-node-redis-nginx-1 Created
```
2. 在Docker Desktop面板查看整套应用栈；选中整个应用栈即可一键删除所有相关容器。

通过对比能看出：相比容易出错的多条 `docker run`，Docker Compose 管理多容器应用启停非常简洁。
