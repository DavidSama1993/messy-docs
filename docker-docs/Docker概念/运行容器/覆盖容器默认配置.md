# 覆盖容器默认配置（Overriding container defaults）
## 讲解
Docker 容器启动时，会执行镜像配置里指定的程序或命令。镜像自带一套默认参数，大部分场景可以直接使用，但你可以按需修改，让容器里的程序按你的预期运行。

举例：已有一个正在运行的数据库容器占用默认端口，想要再启动一个同数据库实例，就需要修改新容器的端口避免冲突；业务负载高时，可以给容器调高可用内存；也可以设置环境变量，给程序传入配置信息。

`docker run` 提供大量参数用来覆盖镜像默认配置、自定义容器行为，下面是几种常用方式：

### 覆盖网络端口
开发、测试时经常需要多套数据库实例同时运行，端口重复就会冲突。使用 `-p` 参数做端口映射，就可以启动多个同镜像容器：
```console
$ docker run -d -p HOST_PORT:CONTAINER_PORT postgres
```

### 设置环境变量
下面这条命令会在容器内部定义环境变量 `foo=bar`：
```console
$ docker run -e foo=bar postgres env
```
输出示例：
```console
HOSTNAME=2042f2e6ebe4
foo=bar
```

> 💡 提示
> `.env` 文件可以批量管理环境变量，不用在命令行写一大堆 `-e`。配合 `--env-file` 使用：
> ```console
> $ docker run --env-file .env postgres env
> ```

### 限制容器资源占用
`--memory` 和 `--cpus` 用来限制容器最大可使用内存与CPU。例如给 Python API 容器设置资源上限，防止它耗尽宿主机资源：
```console
$ docker run -e POSTGRES_PASSWORD=secret --memory="512m" --cpus="0.5" postgres
```
这条命令限制容器最多使用 512MB 内存、0.5 个CPU核心。

> **实时查看资源占用**
> `docker stats` 命令监控正在运行容器的资源使用情况，方便判断资源配额是否合适。

灵活使用这些参数，就能按需调整容器化应用的运行行为。

## 动手实践
本节实操，通过 `docker run` 覆盖容器默认配置。
### 启动多个 Postgres 数据库实例
1. 启动第一个 Postgres 容器
```console
$ docker run -d -e POSTGRES_PASSWORD=secret -p 5432:5432 postgres
```
后台运行，容器内5432端口映射到宿主机5432。

2. 启动第二个，使用不同宿主机端口
```console
$ docker run -d -e POSTGRES_PASSWORD=secret -p 5433:5432 postgres
```
容器内部依然是5432，宿主机端口改为5433，避免端口冲突。

3. 在 Docker Desktop 的 Containers 面板，确认两个容器都正常运行。

### 在自定义网络中运行 Postgres
容器默认接入**默认桥接网络（bridge network）**，它像一个虚拟网桥：同一宿主机上的容器可以互相通信，同时和外部隔离。
但默认桥接有局限，你可以创建自定义网络，通过 `--network` 将容器接入自定义网络。不指定 `--network` 的容器都会连到默认桥接。

1. 创建自定义网络
```console
$ docker network create mynetwork
```
2. 查看所有网络
```console
$ docker network ls
```
列表里能看到刚创建的 `mynetwork`。

3. 把 Postgres 接入自定义网络
```console
$ docker run -d -e POSTGRES_PASSWORD=secret -p 5434:5432 --network mynetwork postgres
```
容器映射宿主机5434端口，并加入 `mynetwork`。使用 `docker network inspect` 可以查看容器是否绑定该网桥。

> 默认桥接 vs 自定义网桥 核心区别
> 1. DNS解析：默认桥接里容器只能靠IP互相访问（`--link` 属于旧方案，不推荐生产使用）；自定义网络支持**容器名直接解析**。
> 2. 隔离性：所有未指定网络的容器都进默认网桥，无关容器之间也能互通，有安全风险；自定义网络是隔离域，只有加入该网络的容器才能互相通信。

### 资源管控
容器默认没有资源上限。在多用户共享服务器上，必须做资源限制，防止单个容器吃光宿主机内存。
```console
$ docker run -d -e POSTGRES_PASSWORD=secret --memory="512m" --cpus=".5" postgres
```
`--cpus` 设置CPU配额，这里是0.5核；`--memory` 设置内存上限512MB。

### 在 Docker Compose 里覆盖 CMD / ENTRYPOINT
有时候需要覆盖镜像内置的启动命令 `CMD` 或者入口 `ENTRYPOINT`，Compose 中可以直接配置：
1. 新建 `compose.yml`
```yaml
services:
  postgres:
    image: postgres:18
    entrypoint: ["docker-entrypoint.sh", "postgres"]
    command: ["-h", "localhost", "-p", "5432"]
    environment:
      POSTGRES_PASSWORD: secret 
```
这个服务使用官方 Postgres18 镜像，自定义入口脚本与启动参数，设置数据库密码。

2. 后台启动服务
```console
$ docker compose up -d
```

3. 在 Docker Desktop 面板选中该容器，点 Exec 进入容器终端，执行命令连接数据库：
```bash
# psql -U postgres
```

> 注意：Postgres镜像本地访问默认是信任认证，**容器内部访问localhost登录可能不需要密码**；但从其他容器或外部主机连接时，就需要密码。

### 使用 docker run 直接覆盖 CMD / ENTRYPOINT
```console 
$ docker run -e POSTGRES_PASSWORD=secret postgres docker-entrypoint.sh -h localhost -p 5432
```
启动 Postgres、设置密码环境变量、覆盖默认启动参数。
