# 与容器共享本地文件（Sharing local files with containers）

## 讲解

容器自带运行所需全部依赖，不依赖宿主机预先安装的软件。容器运行在隔离环境中，对宿主机和其他容器的影响很小。隔离带来一大好处：最大限度避免和宿主机、其他容器产生依赖冲突。但隔离同时也意味着：**默认情况下容器无法直接访问宿主机上的文件**。

举个场景：Web应用容器需要读取宿主机上的配置文件，文件里存放数据库账号、API密钥这类敏感信息。如果直接把敏感信息打包进镜像，镜像分享时就会存在安全风险。为解决这个问题，Docker 提供存储方案打通容器隔离与宿主机数据访问。

Docker 提供两种主要存储方式，用来持久化数据、在宿主机和容器之间共享文件：**卷（volumes）** 和 **绑定挂载（bind mounts）**。

### 卷 vs 绑定挂载

- 卷：容器内部生成、修改的数据，就算容器停止也需要保留时，优先选择卷。可以回看【容器数据持久化】了解卷和适用场景。
- 绑定挂载：如果你要把宿主机上指定的文件/目录直接共享给容器（例如配置文件、开发代码），就用绑定挂载。相当于在宿主机和容器之间开了一条直通通道，非常适合开发环境，满足宿主机与容器实时同步文件的需求。

### 宿主机和容器之间共享文件

`docker run` 的 `-v`（全称 `--volume`）和 `--mount` 参数都可以实现本地文件/目录共享到容器，但行为、用法有重要区别：

- `-v`：写法简单，适合基础卷、绑定挂载场景。如果 `-v` 指定的宿主机路径不存在，Docker 会自动创建该目录。

举个开发场景：你的代码放在宿主机源码目录，编译产物输出到 `/HOST/PATH`，希望容器内可以读到这些产物，并且每次重新编译后容器自动拿到最新文件。绑定挂载写法：

```
$ docker run -v /HOST/PATH:/CONTAINER/PATH -it nginx
```

- `--mount`：功能更丰富、控制更精细，适合复杂挂载场景或生产环境。**默认情况下，如果宿主机上的源路径不存在，`docker run 不会自动创建，而是直接报错`**。

```
$ docker run --mount type=bind,source=/HOST/PATH,target=/CONTAINER/PATH,readonly nginx
```

> 
> 💡 提示
> Docker 官方推荐优先使用 `--mount` 语法。它对挂载流程管控更强，能避免宿主机目录缺失带来的隐性问题。

### Docker访问宿主机文件的权限

使用绑定挂载时，必须保证Docker拥有访问宿主机目录的权限。可以在 `-v` / `--mount` 后增加权限标识：`ro`（只读 read-only）、`rw`（读写 read-write）。

读写示例：

```
$ docker run -v HOST-DIRECTORY:/CONTAINER-DIRECTORY:rw nginx
```

- 只读绑定挂载：容器只能读取宿主机文件，不能修改、删除；防止容器误改动宿主机原始文件。
- 读写绑定挂载：容器可以修改、删除挂载文件，改动会直接同步到宿主机。

> 
> **同步文件共享（Synchronized File Share）**
> 代码库很大时，传统绑定挂载会变慢，高频读写场景尤其明显。同步文件共享依托同步文件缓存机制提升绑定挂载性能，加速宿主机与虚拟机之间的文件访问。

## 动手实践

本节实操，创建绑定挂载，实现宿主机和容器之间共享文件。

### 启动容器

1. 安装 Docker Desktop
2. 用 httpd 镜像启动容器

```
$ docker run -d -p 8080:80 --name my_site httpd:2.4
```

后台启动 httpd 服务，容器80端口映射到宿主机8080。
3. 浏览器访问 [http://localhost:8080，或者](http://localhost:8080%EF%BC%8C%E6%88%96%E8%80%85) curl 验证：

```
$ curl localhost:8080
```

### 使用绑定挂载

绑定挂载可以把宿主机配置文件映射到容器内指定路径。本例通过挂载自定义页面，修改网页内容：

1. 在Docker面板删除刚才的 `my_site` 容器
2. 在宿主机新建目录 `public_html`

```
$ mkdir public_html
```

3. 进入目录，新建 `index.html`，内容如下：

```
<!DOCTYPE html>
<html lang="en">
<head>
<meta charset="UTF-8">
<title> My Website with a Whale & Docker!</title>
</head>
<body>
<h1>Whalecome!!</h1>
<p>Look! There's a friendly whale greeting you!</p>
<pre id="docker-art">
   ##         .
  ## ## ##        ==
 ## ## ## ## ##    ===
/"""""""""""""""""\___/ ===
{                       /  ===-
\______ O           __/
 \    \         __/
  \____\_______/

Hello from Docker!
</pre>
</body>
</html>
```

4. 启动容器，下面 `-v` 和 `--mount` 两种写法效果一致，不要同时执行：
**-v 写法**

```
$ docker run -d --name my_site -p 8080:80 -v .:/usr/local/apache2/htdocs/ httpd:2.4
```

**--mount 写法**

```
$ docker run -d --name my_site -p 8080:80 --mount type=bind,source=./,target=/usr/local/apache2/htdocs/ httpd:2.4
```

> 
> 💡 提示
> Windows PowerShell 使用挂载时，不能直接写 `./`，需要填写绝对路径；Mac / Linux 的 bash 支持相对路径。

启动完成后访问 [http://localhost:8080，就能看到自定义的网页。](http://localhost:8080%EF%BC%8C%E5%B0%B1%E8%83%BD%E7%9C%8B%E5%88%B0%E8%87%AA%E5%AE%9A%E4%B9%89%E7%9A%84%E7%BD%91%E9%A1%B5%E3%80%82)

### 在Docker Desktop面板查看挂载文件

1. 选中容器，切换到 **Files** 标签页，进入 `/usr/local/apache2/htdocs/`，选中文件打开编辑器查看内容。
2. 在宿主机删除这个 html 文件，回到面板，容器内该文件也消失，验证双向同步。
3. 在宿主机重新创建html文件，面板里文件会再次出现，网页也可以正常访问。

### 停止容器

1. 在Docker Desktop进入 **Containers** 页面
2. 找到目标容器
3. 在操作列选择 Stop
