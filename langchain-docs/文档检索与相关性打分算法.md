# 文档检索与相关性打分算法 · 会话知识整理

> 本文档整理自一次关于 RAG 检索技术的连续问答，涵盖 **RRF（倒数排名融合）、HyDE（假设性检索）、BM25、TF-IDF、文档相关性打分算法总览**，最终串联成完整的 RAG 混合检索链路。

---

## 1. RRF（Reciprocal Rank Fusion，倒数排名融合）

**RRF 是 RAG / 检索领域最常用的多路结果融合算法**，用来合并多组排序列表（典型：BM25 关键词检索 + 向量检索），**不需要对齐分数，只看排名位置**。

### 公式

$$\text{RRF}(d) = \sum_{r\in R} \frac{1}{k + \text{rank}_r(d)}$$

- `d`：文档
- `R`：各个检索器（BM25、向量库等）
- `rank_r(d)`：文档 d 在检索器 r 里的名次，从 1 开始；不在列表里则贡献 0
- `k`：平滑常数，行业默认 **60**

### 直观例子（k=60）

| 排名 | 得分 |
|---|---|
| rank=1 | 1/(60+1) ≈ 0.0164 |
| rank=10 | 1/(60+10) ≈ 0.0143 |
| rank=100 | 1/(60+100) = 0.00625 |

**核心思想**：多个检索渠道都靠前的文档，总分更高，奖励共识；解决 BM25 和向量相似度分数值域不一样、没法直接相加的痛点。

### 优点
- 不用分数归一化，鲁棒
- 计算极快，开销很小
- 主流向量库/搜索服务原生支持：Weaviate、OpenSearch、Azure AI Search、MongoDB Atlas 等

### 典型使用场景
1. Hybrid Search 混合检索（BM25 + 向量）
2. RAG-Fusion：同一个 query 扩成多个变体分别检索，RRF 合并结果
3. 多路召回融合（多路不同 embedding 模型召回）

### 其他 RRF 释义（简记）
- RRF（Residual Renal Function）残余肾功能（肾内科）
- RRF（Recovery and Resilience Facility）欧盟复苏基金

## 2. HyDE（Hypothetical Document Embeddings，假设性检索）

**论文**：《Precise Zero-Shot Dense Retrieval without Relevance Labels》（2022），RAG 里经典的**查询侧检索增强方案**。

### 核心思想（反常识）
**不拿用户问题直接 embedding 检索；先让 LLM 生成一段"假想的答案文档"，再对这个假想文档做 embedding 去搜真实知识库。**

> 重点：**假想文档只做检索线索，不直接给用户；它可以幻觉、事实错，只要语义、用词风格贴近库里真实文档就行。**

### 完整流程
1. 用户 Query：`RRF公式是什么？`
2. LLM 生成假设文档（示例）："RRF全称 Reciprocal Rank Fusion 倒数排名融合，用于多路检索结果融合。公式为 Σ 1/(k+rank)，k 一般取 60，不依赖原始分数，只靠排名加权，常用于 BM25+向量混合检索。"
3. 对假设文本做 embedding
4. 向量库 ANN 检索，召回真实 chunk
5. 召回结果（真实文档）送入最终生成，给用户回答

### 为什么好用？
解决 **Query-Document 不对称问题**：
- Query：短、问句形式、词汇少、口语化
- 知识库 Chunk：陈述句、解释型、术语多、篇幅长

Embedding 空间里，问句向量天然很难匹配陈述句向量；HyDE 把检索变成**文档-文档相似度匹配**，这正是对比学习 embedding 模型最擅长的任务。

### 优缺点
**优点**
- 短 query、模糊 query、零样本检索场景召回提升明显
- 实现简单，不需要训练，即插即用
- 适合术语错位、用户描述和文档措辞不一样的场景

**缺点**
- 多一次 LLM 调用：延迟↑、token 成本↑
- 风险：LLM 假设文档跑偏 → 检索方向被带偏（幻觉污染检索意图）
- 精确实体检索（订单号、编号、法条原文）反而不如原生 query / BM25

### 和 RRF 怎么搭配（面试高频）
标准混合召回链路：
> 用户 query → 两路召回
> ① BM25 原始关键词召回
> ② HyDE 生成假设文档 → 向量召回
> 两路结果 → **RRF 融合** → 重排（Rerank）→ 送入 LLM 生成答案

### 容易混淆的几个检索增强
- Query 改写：改写原问题，还是**问句**
- 子查询（Multi-query）：拆成多个小问题，多个 query 检索
- HyDE：生成**答案式段落**（假设文档）

### 落地工程建议
1. 双路召回兜底：**HyDE 向量 + 原始 query 向量 + BM25** 三路，RRF 融合，防止 HyDE 跑偏直接搜空
2. Prompt 约束：不要写很长，控制成 1~3 段、贴近文档风格，不要发散
3. 评测优先看 nDCG/召回，不是看假设文档写得对不对
4. 实体类、精确查找场景不要默认开 HyDE

## 3. BM25（Okapi BM25）

**BM25 是概率检索模型，用来计算 query 和文档的相关性打分，属于稀疏词袋检索，ES/Lucene、Milvus、RAG 混合召回标配。**

### 公式

$$\text{score}(Q,d)=\sum_{t\in Q} \text{IDF}(t)\cdot \frac{\text{tf}(t,d)\cdot(k_1+1)}{\text{tf}(t,d)+k_1\cdot\left(1-b+b\cdot\frac{|d|}{\text{avgdl}}\right)}$$

IDF 平滑式（Lucene 常用）：

$$\text{IDF}(t)=\log\left(1+\frac{N-n_t+0.5}{n_t+0.5}\right)$$

### 参数说明
- `tf(t,d)`：词 t 在文档 d 中出现次数
- `|d|`：文档长度（token 数）
- `avgdl`：全库文档平均长度
- `N`：总文档数；`n_t`：包含词 t 的文档数
- `k1`：**词频饱和系数，默认 1.2**，控制词频增长的上限；k1 越小，词频很快饱和，防止关键词堆砌刷分
- `b`：**长度归一系数，默认 0.75**，b=1 完全归一，b=0 不做长度惩罚，抑制长文档天然优势

### 和 TF-IDF 的核心差别
1. TF-IDF：词频贡献近似线性上涨，长文档、关键词堆砌容易虚高；**无内置长度归一**
2. BM25：
   - TF 饱和：词出现很多次之后，收益边际递减，分数不会无限涨
   - 内置文档长度归一，长短文本打分更公平
   - 带平滑的 IDF，避免除 0；基于概率检索框架，不是向量空间启发式模型

### 优缺点
**优点**
- 速度快，基于倒排索引，CPU 开销低、可解释
- 对**专有名词、编号、精确关键词**召回很强（RAG 里很适合抓术语、代码名、ID）
- 参数可调，适配长短文本数据集

**缺点**
- 词袋模型：**无视语序、没有语义理解**，同义词、改写、转述匹配不到
- 不能理解否定、句式差异，字面不一样就匹配失败
- 无法处理一词多义

### RAG 中的用法
工业主流：**BM25 + Embedding 向量检索（稠密）做混合召回（Hybrid）**
- BM25：抓硬关键词、实体、专业术语（精确匹配）
- 向量检索：抓语义相似、同义改写、自然语言转述
- 两路召回结果再用 RRF（倒数排名融合）合并

### 变种
- BM25F：多字段版本，不同字段（标题/正文）给不同权重
- BM25+：对低频词增加小偏移，改善短文档召回
- BM25L：改进长度归一，适合文档长度差异极大的数据集

## 4. TF-IDF

**TF-IDF = 词频(TF) × 逆文档频率(IDF)**，经典词袋相关性打分算法，衡量一个词对某篇文档的重要程度。

> 核心思想：一个词在这篇文档里出现得多（TF 高），同时在整个语料库大部分文档里很少出现（IDF 高）→ 这个词很有区分度。

### 公式
**TF（Term Frequency，词频）**

$$\text{TF}(t,d) = \frac{\text{词}t\text{在文档}d\text{出现次数}}{\text{文档}d\text{总词数}}$$

（简化版本直接用原始次数 count(t,d)）

**IDF（Inverse Document Frequency，逆文档频率）**

$$\text{IDF}(t) = \log\left(\frac{N}{n_t}\right)$$

- `N`：全部文档总数
- `n_t`：包含词 t 的文档数量

工程上会加平滑，防止分母为 0：

$$\text{IDF}(t) = \log\left(\frac{N+1}{n_t+1}\right)+1$$

**TF-IDF 分值**

$$\text{TF-IDF}(t,d) = \text{TF}(t,d) \times \text{IDF}(t)$$

### 核心特点
**优点**
- 简单、可解释、计算快，基于倒排
- 自动压低通用停用词（"的、是、the"，几乎所有文档都有，IDF 很低）

**缺点**
1. TF 线性增长：词反复堆砌分数持续上涨，容易被关键词堆砌作弊
2. 没有原生文档长度归一：长文档天然更容易拿到高分
3. 词袋模型：**不看语序、没有语义**，同义词无法匹配
4. IDF 只统计文档覆盖，没有 BM25 的概率检索理论支撑

### TF-IDF vs BM25（精简对照）

| 特性 | TF-IDF | BM25 |
|---|---|---|
| TF 增长 | 线性，越高越好 | 饱和，词频到一定程度不再加分 |
| 文档长度 | 无内置归一 | 内置长度惩罚（参数 b） |
| 理论基础 | 启发式统计 | Okapi 概率检索模型 |
| 适用场景 | 关键词特征提取、简单检索 | 搜索引擎、RAG 稀疏召回（主流） |

### 常见用途
1. 文本特征：把文本转为 TF-IDF 向量，喂给朴素贝叶斯、SVM 做文本分类
2. 简单关键词检索（检索场景基本被 BM25 替代）
3. 提取文档关键词：取 TF-IDF 最高的一批词

## 5. 文档相关性打分算法总览

按大类划分：**稀疏词袋类（字面匹配）、稠密向量类（语义匹配）、重排模型（精细打分）、传统概率/统计模型**。

> 检索链路一般：多路召回（稀疏+稠密）→ 结果融合（RRF）→ 重排（Reranker），每一步都有打分。

### 5.1 稀疏检索（基于词，倒排索引，关键词匹配，可解释）

| 算法 | 说明 |
|---|---|
| **TF-IDF** | score = TF × IDF；TF 线性增长，无原生长度归一；多用于关键词提取、文本分类 |
| **Okapi BM25** | 工业稀疏召回首选（ES 默认）；TF 饱和 + 自带长度归一 |
| **BM25+ / BM25L** | BM25+ 改善极短文档召回；BM25L 适合文档长度差异极大的数据集 |
| **DFR、PL2** | 基于泊松分布的概率检索模型，Lucene 备选，RAG 很少用 |
| **Boolean 布尔检索** | 命中/不命中（AND/OR/NOT），先过滤再交给其他算法打分 |

### 5.2 稠密向量检索（Embedding，语义打分，RAG 核心）

**打分本质是向量相似度**：

1. **余弦相似度 Cosine Similarity（最常用）**

$$\cos(\boldsymbol q,\boldsymbol d)=\frac{\boldsymbol q\cdot \boldsymbol d}{||\boldsymbol q||\cdot||\boldsymbol d||}$$

值域 [-1,1]，越接近 1 越相关；向量归一化后等价于内积。

2. **内积 Dot Product**：适合 Matryoshka、DPR、BGE 这类训练时就优化内积的模型；向量模长会影响分数
3. **欧氏距离 L2 Distance**：距离越小越相似；归一向量下和余弦单调等价

特点：理解同义、转述；但丢失精确关键词信息、不可解释、向量库开销更大。
配套优化：**HyDE（假设文档）**，把 query 扩写成虚拟文档再向量化，提升稠密召回质量。

### 5.3 多路结果融合算法

**RRF（倒数排名融合）** 是工业混合召回标配：

$$\text{RRFscore}(d) = \sum_{r\in \text{rankers}} \frac{1}{k + rank_r(d)}$$

- 不依赖两路打分的原始分值（BM25 分和余弦相似度值域完全不一样，不能直接相加），只依赖排名位置
- 同类算法：RBO、CombSUM、CombMNZ；RRF 最简单稳定，RAG 首选

### 5.4 重排模型 Reranker（召回后精细二次打分，精度最高）

1. **Cross-Encoder（交叉编码器）**：输入 `[CLS] query [SEP] doc [SEP]`，直接输出 0~1 相关性分数。精度天花板，但速度慢，只能 rerank 小候选集。代表：BGE-Reranker、Jina-Reranker、Cohere Rerank
2. **ColBERT（晚交互 late-interaction）**：介于 Dense 和 CrossEncoder 之间，细粒度 token 级匹配，兼顾速度和精度，支持索引预构建

### 5.5 其他经典模型（了解即可）

1. **Language Model 语言模型（Query Likelihood，查询似然模型）**：文档 d 生成查询 Q 的概率 P(Q|d)，概率越高越相关，常用 Dirichlet 平滑
2. **PageRank / HITS**：链接相关性，网页检索，不适合纯文本知识库

### 对比速记（RAG 视角）

| 算法 | 匹配维度 | 打分依据 | 典型位置 |
|---|---|---|---|
| BM25 | 字面关键词 | 词频+文档概率统计 | 召回（稀疏） |
| 余弦相似度 | 语义 | embedding 向量距离 | 召回（稠密） |
| RRF | 融合多路排名 | 排名位置 | 召回结果合并 |
| CrossEncoder | 细粒度语义 | query+doc 联合编码 | 重排 rerank |

### 标准 RAG 检索链路（串联全部知识点）

> Query → HyDE（可选）
> → BM25 稀疏召回 + Embedding 稠密召回
> → RRF 融合两路列表
> → CrossEncoder Reranker 重新打分排序
> → 取 TopK 喂给 LLM

### 关键取舍口诀
- 要**精确实体、编号、专业术语**：靠 BM25
- 要**同义改写、语义理解**：靠 Embedding 余弦
- 两路都要：混合召回 + RRF
- 想要更高精度：后面加 Reranker
